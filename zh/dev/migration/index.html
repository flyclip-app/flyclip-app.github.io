FlyClip 拥有独立且现代化的扩展规范体系（基于 YAML 与轻量 QuickJS）。为了方便开发者将已有的 PopClip 动作快速移植到 FlyClip，您可以通过下方的在线转换工具一键将旧版 Config.plist 或代码重构为 FlyClip 现代扩展。

迁移前提须知：绝大多数旧版 PopClip 扩展无法直接在 Windows 下运行

网络上现存的很多 .popclipext 包采用了旧式 Config.plist 或 macOS 独有的 AppleScript / Bash 脚本。在 FlyClip 中，只有使用了 Config.yaml / Config.json 且动作是通用逻辑（URL / JS / 按键）的扩展才能被读取。包含 macOS 专属逻辑或旧 plist 的扩展必须使用上方工具转换配置文件并重构脚本。

1. PopClip 与 FlyClip 语法与功能全景对照表

对比维度FlyClip (Windows / 跨平台)PopClip (macOS 专属)兼容性与迁移说明
扩展包目录格式.flyclipext.popclipext⚠️ 需包含 YAML：FlyClip 扫描两种目录名，但包内必须包含 Config.yaml 或 Config.json。
单文件归档格式.flyclipextz.popclipextz⚠️ 解压后必须含 YAML：支持双击解压安装，解压后必须包含有效 YAML。
配置文件格式Config.yaml / Config.jsonConfig.yaml / Config.plist❌ 已废弃 plist：旧版 Config.plist 会明确报错拒绝，需转换为 YAML。
选区输入对象flyclip.input.textpopclip.input.text✅ 100% 兼容：在 FlyClip 中调 popclip.input.text 完全等价。
正则收窄文本flyclip.input.matchedpopclip.input.matchedText✅ 100% 兼容：matched 与 matchedText 互为别名。
写入剪贴板flyclip.copy(text)popclip.copyText(text)✅ 100% 兼容：两个函数完全等价可用。
触发粘贴flyclip.paste(text?)popclip.pasteText(text)✅ 100% 兼容：flyclip.paste() 还支持不传参保留现有剪贴板粘贴。
读取剪贴板纯文本flyclip.readClipboard()pasteboard.text✅ 双向支持：既可调用 readClipboard()，也可读取 pasteboard.text。
异步延时等待await sleep(ms)await sleep(ms)✅ 完全一致：均为内置全局 Promise 函数。
Base64 编解码btoa(str) / atob(b64)btoa(str) / atob(b64)✅ 完全一致：标准 Web API 全局可用。
调用本地 CLI 命令行flyclip.run(cmd, args)❌ 受沙盒限制无法直接调用🌟 同步函数（无需 await）：直接返回 { stdout, stderr, code }。
网络 HTTP 请求await flyclip.fetch(url, opts)require("axios")🌟 极速轻量：FlyClip 内置 Rust 原生 HTTP 客户端，零外部 node 依赖。
